REVERSE ENGINEERING / OEA CYBER CHALLENGE 2026

Señales secretas: firmware ESP32, punteros y un mensaje Morse

De una tabla de símbolos ELF a 21 cadenas Morse: reversing estático, direcciones virtuales, offsets y Python.

16 octubre 2026 · 85 puntos nominales · Media · Lautaro Poggi (xLauta7)

Sobre la autoría y la evidencia: La plataforma aceptó la respuesta YOUREVERSEDMYFIRMWARE. Los offsets, símbolos y hallazgos están registrados en los apuntes. El script Python es una reconstrucción explicativa posterior que debe comprobarse contra el ELF original antes de considerarla una repetición autónoma.

01. Un binario que no podía tratar como texto

El reto entregó challenge.elf, un firmware de ESP32. Era mi primera experiencia extensa examinando un archivo de este tipo. En lugar de ejecutarlo, trabajé en Ubuntu bajo WSL2 para hacer análisis estático: buscar símbolos, estudiar secciones y relacionar bytes con direcciones.

Un ELF almacena código, datos, símbolos y metadatos. Una cadena que buscamos puede no estar escrita directamente: puede ser el resultado de seguir referencias. Esa diferencia fue el centro del ejercicio.

02. La pista en la tabla de símbolos

Busqué nombres relacionados con posibles mensajes. Apareció un símbolo global llamado morse, de tipo OBJECT, tamaño 84 bytes y dirección virtual 0x3ffbdb60.

bash
file challenge.elf
nm -a challenge.elf | grep -Ei 'morse|signal|secret|flag|message' | head -n 30
readelf -sW challenge.elf | grep -w morse
readelf -SW challenge.elf

El tamaño dio una pista que después cobró sentido: 84 / 4 = 21. El arreglo contenía 21 punteros de cuatro bytes, no un texto plano de 84 caracteres.

03. De dirección virtual a offset de archivo

El símbolo estaba en .dram0.data. En las notas quedó el offset 0x14b60, donde podía examinarse la tabla con xxd. Los punteros eran enteros de 32 bits en orden little-endian.

bash
xxd -s 0x14b60 -l 84 challenge.elf
xxd -s 0x1120 -l 160 challenge.elf

Las referencias apuntaban hacia .flash.rodata, con dirección virtual base 0x3f400120 y offset de archivo 0x1120. Allí aparecieron secuencias como -.--, --- y ..-, separadas por bytes nulos.

text
offset_en_archivo =
  offset_base_archivo + (direccion_del_puntero - direccion_base_virtual)

Esta fórmula permite pasar de una dirección indicada por el programa al lugar donde están sus bytes en el fichero. Comprender que dirección virtual y offset no son lo mismo fue uno de los aprendizajes principales.

04. Extraer las 21 cadenas

El siguiente script resume la técnica. Fue elaborado como reconstrucción y no representa una copia literal del código tecleado durante el CTF:

python
from pathlib import Path
import struct

elf = Path("challenge.elf").read_bytes()

punteros_offset = 0x14B60
cantidad = 84 // 4
rodata_dir_virtual = 0x3F400120
rodata_offset_archivo = 0x1120

codigos = []
for i in range(cantidad):
    puntero = struct.unpack_from("<I", elf, punteros_offset + i * 4)[0]
    offset_cadena = rodata_offset_archivo + (puntero - rodata_dir_virtual)
    fin = elf.index(b"\x00", offset_cadena)
    codigos.append(elf[offset_cadena:fin].decode("ascii"))

print(" ".join(codigos))

La expresión <I indica un entero sin signo de cuatro bytes en formato little-endian; elf.index(b'\x00', ...) localiza el terminador nulo. El resultado del script es una lista de símbolos Morse, no el texto final.

05. Decodificación y resultado

Las 21 secuencias se llevaron a CyberChef → From Morse Code. Se obtuvo YOUREVERSEDMYFIRMWARE, y la plataforma aceptó esa cadena exacta, sin el envoltorio flag{}.

La secuencia de razonamiento fue: símbolo → sección → offset → bytes → punteros → Morse → mensaje. No fue necesario ejecutar firmware de una arquitectura distinta a la máquina de análisis.

06. Lo que tengo que poder repetir

  • Utilizar file, nm y readelf para identificar formatos y estructuras.
  • Explicar por qué 84 bytes corresponden a 21 punteros de 4 bytes.
  • Convertir direcciones virtuales a offsets usando las bases de sección correctas.
  • Interpretar datos little-endian sin confundirlos con cadenas.
  • Volver al ELF original y reproducir la extracción sin copiar el script.

Este reto fue uno de los más significativos de mi primer CTF: me mostró cómo una respuesta puede aparecer al conectar evidencias pequeñas, no necesariamente al ejecutar una herramienta que haga todo por mí.
